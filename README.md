# gohome · 퇴근길 교통정보

실행하면 아래 두 가지를 한 화면에 보여주는 (아주 지극히) 개인용 Windows 데스크톱 앱입니다.

- **왼쪽:** 금천07 마을버스 · JNK디지털타워(17635) 도착정보
- **오른쪽:** 1호선 가산디지털단지역 **독산 방면** 도착정보 (급행 포함)

실행하자마자 1회 조회하고, 이후 **60초마다 자동으로 조회**합니다 (조회 버튼을 누르면 바로 조회하고 그 시점부터 다시 60초). 창을 닫으면 자동 조회도 즉시 멈춥니다.

---

## 1. 실행 방법

### EXE로 실행
`dist\gohome.exe`를 더블클릭합니다. 같은 폴더에 `.env` 파일이 있어야 합니다.

### 소스에서 실행 (개발용)
```bat
py -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python main.py
```

## 2. API KEY 설정

`.env.example`을 `.env`로 복사한 뒤 값을 입력합니다. 이 저장소의 `.env`에는 이미 발급받은 키가 들어 있습니다.

```env
SEOUL_BUS_API_KEY=...     # data.go.kr  서울특별시_버스도착정보조회 서비스
SEOUL_SUBWAY_API_KEY=...  # data.seoul.go.kr  실시간 지하철 인증키
MOCK_MODE=false
```

- `.env`는 `.gitignore`에 들어 있어 git에 올라가지 않습니다. API KEY는 소스코드에 없습니다.
- `.env`를 찾는 순서는 **EXE(또는 프로젝트) 폴더 → 현재 작업 폴더**입니다. OS 환경변수가 있으면 그 값을 먼저 사용합니다.
- 키가 없으면 화면 상단에 안내 문구가 표시됩니다.
- 로그(`gohome.log`)에는 요청 URL을 남기지 않습니다. 키가 섞여 들어가더라도 `****`로 마스킹됩니다.

## 3. Mock 모드

`.env`에서 `MOCK_MODE=true`로 바꾸고 앱을 다시 실행합니다.
API를 호출하지 않고 버스 2건, 일반열차 3건, 급행열차 2건을 표시합니다.
Mock 모드에서는 상단에 주황색 **MOCK 모드 · 테스트 데이터** 배지가 나오고, 각 카드에도 **테스트 데이터** 태그가 붙습니다.
실제 모드에서는 테스트 데이터를 만들지 않습니다.

## 4. EXE 빌드

> EXE 빌드는 **Windows에서** 해야 합니다. PyInstaller는 크로스 컴파일을 지원하지 않습니다.

1. Windows에 Python 3.10 이상을 설치합니다.
2. `build.bat`을 더블클릭합니다. 가상환경 생성 → 패키지 설치 → 테스트 → PyInstaller 빌드 순으로 진행됩니다.
3. 결과물은 `dist\gohome.exe`(단일 파일, 콘솔 창 없음)와 `dist\.env`입니다.

`dist` 폴더를 통째로 복사하면 Python이 설치되지 않은 PC에서도 실행됩니다. `.env`는 EXE 옆에 두고 따로 관리합니다.

### 아이콘
`assets/gohome.ico`가 EXE와 창 아이콘으로 쓰입니다. 원본 이미지는 `assets/icon_source.png`입니다. 아이콘을 바꾸려면 다음 순서로 실행합니다.
```bat
.venv\Scripts\python tools\make_icon.py 새이미지.png
build.bat
```
인자 없이 실행하면 기본 집 모양 아이콘이 만들어집니다.

## 6. 실제 API 검증 결과 (2026-11-20)

### 버스 — 서울특별시_버스도착정보조회 서비스
- 사용 엔드포인트: `GET http://ws.bus.go.kr/api/rest/arrive/getArrInfoByRoute?serviceKey&stId&busRouteId&ord&resultType=json`
- 설정 파일: `config/settings.py`

| 항목 | 값 | 비고 |
|---|---|---|
| 노선 | 금천07 → `busRouteId=117900007` | `getArrInfoByRouteAll`로 확인 |
| 정류장 표시번호 | `arsId=17635` | 정류장 표지판 번호 |
| 정류소 내부 ID | `stId=116900298` | arsId와 다른 값 |
| 노선상 순번 | `ord=27` | |

- **방향 확인 결과:** 금천07 경로는 `… 구로디지털단지역(25) → 구로디지털단지입구(26) → JNK디지털타워(27) → 에이스하이엔드타워2차(28) → … → 가산디지털단지역3번출구(35) → 독산역(40) → … → 시흥1동`입니다.
  - 17635에서 타는 버스는 **가산디지털단지역·독산역 방면**입니다. 요청서에 적힌 "구로디지털단지역 방면"과 반대입니다.
  - 금천07은 17635에 한 방향으로만 정차합니다. 반대 방향 정류장은 17634(구로디지털단지우체국) 등입니다.
- **사용 필드:**
  - `traTime1/2`: 도착 예정(초). `mkTm`(데이터 생성 시각)부터 지난 시간을 빼서 표시합니다.
  - `arrmsg1/2`: `곧 도착`, `출발대기`, `운행종료` 판별
  - `sectOrd1/2`: 남은 정류장 수 계산
  - `stationNm1/2`: 버스 현재 위치
  - `isLast1/2`: 막차 여부
- 이 키로는 노선정보·정류소정보 서비스(`busRouteInfo`, `stationinfo`)를 호출하면 401이 납니다(활용신청 안 됨). 그래서 ID는 고정값으로 관리합니다.

### 지하철 — realtimePosition (실시간 열차 위치)
- 사용 엔드포인트: `GET http://swopenAPI.seoul.go.kr/api/subway/{KEY}/json/realtimePosition/0/300/1호선`
  - 키는 기존 실시간 지하철 키를 그대로 씁니다.
- **처음엔 `realtimeStationArrival`(역 도착정보)을 썼다가 바꿨습니다.** 실측해 보니 1호선에서 이런 문제가 있었습니다.
  - 도착 예정시간(`barvlDt`)이 항상 `0`입니다.
  - 방향별로 가장 가까운 2~3대만 줍니다.
  - 위치가 수십 초~수 분 늦게 반영돼, "전역 도착", "가산 도착" 상태로 몇 분씩 멈춰 보였습니다.
  - 같은 열차의 가산 도착이 위치 API보다 약 40초 늦게 들어왔습니다.
- **위치 API의 특징:**
  - 1호선 전체 열차의 현재 역과 상태(`trainSttus`: 0 진입 / 1 도착 / 2 출발)를 줍니다.
  - 같은 열차가 중복으로 오는 경우가 있어, 열차번호별로 최신 행만 사용합니다.
- **방향 판단:** 상행/하행 문자열만 보지 않고 실제 역 위치로 판단합니다. 아래를 모두 만족하는 열차만 표시합니다.
  - 1호선(`subwayId 1001`)이고 하행(`updnLine 1`)입니다.
  - 현재 역이 가산으로 들어오는 경로 위에 있습니다.
    - 경로: 경원선 ~ 청량리 ~ 서울 ~ 영등포 ~ 구로. 역 ID `1001000100`~`1001000141`.
    - 역 ID 끝 3자리가 가산 쪽으로 1씩 늘어나므로, 남은 역 수 = `142 - 끝 3자리`입니다. 예: 청량리(124)는 18역 전, 구로(141)는 1역 전.
    - 경인선(구로 이후 오류동·부평 방면, 142~)은 가산을 지나지 않으므로 제외합니다.
  - 행선지(`statnTnm`)가 가산 남쪽 역입니다. 구로행·인천행·광운대행은 가산에 오지 않으므로 제외합니다.
  - **광명행·서동탄행·병점행·수원행은 표시하지 않습니다** (개인 설정, `EXCLUDED_DESTINATIONS`).
  - 급행(`directAt=1`)은 독산에 서지 않지만 가산에는 서므로 표시합니다.
- **가산에 있는 열차:**
  - 출발(`trainSttus` 2) 상태면 숨깁니다.
  - 진입/도착 정보가 2분 넘게 지났으면 이미 떠난 것으로 보고 숨깁니다.
- **도착 시각 (API 값만 사용):**
  - 실시간 API는 1호선 도착 예정시간을 주지 않습니다 (`barvlDt`가 항상 0).
  - 그래서 같은 키로 쓸 수 있는 서울 열린데이터광장 **역별 열차 시간표 API**(`SearchSTNTimeTableByIDService`)를 기준으로 씁니다.
    - 가산디지털단지(역 코드 `1702`) 하행 시간표. 평일/토요일/일요일 구분 (공휴일은 구분하지 않음).
    - 열차번호로 실시간 열차와 연결합니다. 실시간 `0647` = 시간표 `K647`.
    - 시간표의 급행 여부(`EXPRESS_YN` D/G)를 씁니다.
  - **지연 보정:** 실시간 위치의 수신 시각과, 그 역의 시간표 시각(같은 시간표 API)을 비교해 지연을 구합니다.
    - 예상 도착 = 가산 시간표 시각 + 지연. 일찍 와 있는 경우는 시간표 시각 그대로입니다.
    - 역 이름 → 역 코드는 `SearchSTNBySubwayLineInfo`로 찾습니다.
  - 시간표는 운행일마다 한 번만 받습니다 (가산 + 실제로 열차가 있는 역만, 하루 수십 회 이내).
  - 실시간 위치가 없는 열차(아직 출발 전, 예: 구로 출발 신창행)는 **실시간 없음** 태그와 함께 시간표 시각을 보여줍니다. 시간표 시각이 2분 넘게 지나도 위치가 안 잡히면 숨깁니다.
  - 시간표에 없는 실시간 열차는 시각 없이 위치만 보여줍니다.
- **표시:**
  - 각 열차에 **현재 위치**와 **정보 시각**(위치가 확인된 지 몇 분 됐는지)도 함께 보여줍니다.
  - 위치 정보가 5분 넘게 갱신되지 않은 열차에는 **정보 지연** 태그를 붙입니다.
- **정렬:** 예상 도착 순으로, 앞으로 60분 안의 열차를 최대 6건까지 보여줍니다.

### 오류 처리 매핑

| 상황 | 표시 |
|---|---|
| 인터넷 끊김 / 연결 실패 | "인터넷 연결을 확인해 주세요" |
| 타임아웃 (연결 5초 / 응답 10초) | "응답이 지연되고 있습니다" |
| 버스 HTTP 401, `headerCd 5/6/7`, XML 키 오류 / 지하철 `INFO-100` | 인증 실패 안내 |
| HTTP 429, 버스 `headerCd 8` / 지하철 `ERROR-336/337` | 호출 한도 초과 |
| JSON 파싱 실패, 필드 누락 | 형식 오류 안내 (잘못된 행만 건너뜀) |
| 버스 `headerCd 4` / 지하철 `INFO-200` / 필터 후 0건 | "도착정보 없음" |

한쪽 API가 실패해도 다른 쪽 결과는 그대로 표시됩니다. 어떤 오류가 나도 프로그램은 종료되지 않습니다.
